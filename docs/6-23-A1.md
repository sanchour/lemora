# 6-23 A1 · Unicode character reference checkpoint

2026-11-02 · Codex · claim alpha.163; implementation checkpoint alpha.164.
**A1 is implemented and online browser checks passed, but final acceptance remains open.**

## What is reachable

`/cursus/characters` opens from Cursus's header, Marks and the alphabet letter sheet. The letter-sheet
link preserves the actual letter, including combining characters, through the `text` query parameter.
The reference is available without a paid plan. It does not change learner records or grow decks.

Paste a text to inspect its unique code points, in input order, paginated 48 at a time. Details show
the official Unicode name, code point, script, block, general category, simple case pairs, NFC/NFD
and UTF-8 bytes. The full text's normalization has an explicitly bounded preview. Search by literal
character, official English name or `U+`/`0x` code point; browse scripts by block, 96 results per page.
Lookalikes retain sequence mappings such as `m` ↔ `rn`; opening a sequence exposes all its characters.
Typing guidance reuses the current keyboard layout, with its existing practice link. CJK details
reuse the existing Unihan definitions and romaji/Korean readings, labelled with their actual notation.

Private-use, unassigned, noncharacter, control and isolated-surrogate positions are distinguished;
no official names or UTF-8 encodings are invented. Device normalization and font coverage can differ
from the pinned Unicode data. Simple case pairs deliberately exclude expansions such as ß → SS.
The lookalike display is a reference, not a claim of full UTS #39 security conformance.

## Data, source and privacy

`node scripts/script/unicode.ts` regenerates `public/chars/unicode/` from T0's existing, SHA-256-pinned
Unicode 17.0.0 cache. No new source downloads, dependencies or database tables were added.
175 script shards plus the shared index contain 40,470 explicit names, 20 compact range records
and 6,565 confusable mappings. CJK/Tangut and Hangul names follow the Unicode algorithms rather
than expanding the large ranges into hundreds of thousands of JSON rows.

Data JSON totals **3,690,085 raw bytes / 599,962 bytes gzipped individually**. This excludes the small
licence and source-manifest files; the source fixture is test-only and not a browser asset.
The Unicode-3.0 notice and source hashes ship beside the data. The generator writes the immutable
original UnicodeData gzip fixture used for source comparisons in CI. Reproduction needs the original
ignored T0 cache; changing upstream snapshots are rejected by hash rather than silently substituted.
See [T0 provenance](6-23-DATA.md), [UAX #44 for Unicode 17](https://www.unicode.org/reports/tr44/tr44-36.html),
[Hangul name generation](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/#G24646)
and [UTS #39](https://www.unicode.org/reports/tr39/tr39-32.html).

Data loads only on opening the reference; per-script requests stay lazy. Cache-first storage uses
`lingua-unicode-17`, with shape/version validation, retryable failures and an explicit message when
storage fails. Workbox has a matching runtime rule. Generated Unicode JSON is absent from the precache.
Pasted text remains in local component state and is never sent in an asset request. The source fixture
and generated public data contain no learner data or keys.

91 interface messages were added to the six bundled catalogues (es/fr/de/ru/zh/ar), including errors
and category labels; prior entries were not reformatted. Translations were written in this session,
without an external translation request. Native-speaker review is not claimed. Official character
and script names remain source data in English.

## Blocker and exact stop point

A production-preview offline reload was attempted after stopping the local preview server. The
in-app browser navigated to a connection-error page, then its URL policy blocked further inspection
of that internal error page (including console logs). **The offline reload did not pass.** It is
not known whether the cause is app/service-worker behavior or the browser's navigation handling;
no claim that it is an unrelated pre-existing bug is made. No alternative control path or workaround
was used. The existing app shell/service-worker registration was read, not changed.

Following the user's stop rule, this is a **branch checkpoint**, not a merged/deployed completion.
F1306 stays open; Codex retains the A1 claim so another session does not duplicate it. No A2 or later
track is claimed. Next on request: resolve the offline reload/inspection blocker, then finish A1
acceptance and its checked publication. Cached-data unit tests do not substitute for that browser check.

Also not verified: screen readers, native-speaker translations, all six interface locales in a browser,
rare-character font coverage, clipboard behavior, live typing practice behind the paid-plan gate,
real audio/AI/microphone or an installed desktop PWA. No phone work was done.
